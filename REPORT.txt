HeadHunter — עדכון ביצוע וחסמים מאומתים

הושלם:
- הוקם מסד Supabase נפרד: ruejyiromtthygqtpcsy בארגון HeadHunter Preview.
- הורצו בהצלחה שלוש הגירות המסד: 001_initial, 002_workspace, 003_operations.
- היישום המקומי חובר למסד האמיתי באמצעות מפתח ציבורי בלבד.
- הספירות מגיעות מ-count exact במסד. במצב תקלה או לפני קבלת תוצאה מוצג מקף, לא מספר מומצא.
- ספירת משרות מתחשבת במספר הכולל, ולא רק במגבלת שורות של תשובת API אחת.
- נוספו עריכת משרות, רשימת משרות סגורות ופתיחתן מחדש, קטגוריה, מיקום,
  סידור עבודה, ניסיון נדרש וטווח שכר שהארגון מזין במפורש.
- נוספו ביטול מועמדות בידי המועמד והגנה במסד מפני שינוי החלטתו חזרה בידי מגייס.
- נוספו צפייה בחברי צוות, שינוי תפקיד והסרת גישה בידי בעל הארגון.
- נוספו עריכת מועמד, שינוי מאגר לפי הרשאות ומסך שחזור חשבון.
- הוגדרה כתובת החזרה המקומית המדויקת http://localhost:3100 ב-Supabase.

בדיקות שבוצעו:
- 5 בדיקות אוטומטיות עברו: בדיקות לוגיקה, מסננים משולבים ובדיקת PostgreSQL מקומית מרובת תרחישים.
- TypeScript עבר.
- בניית Next.js עם חיבור סביבת הבדיקות עברה. רכיב עריכת המועמד שנוסף לאחר הבנייה אומת ב-TypeScript ובהרצה מקומית.
- בדיקת SQL מול Supabase האמיתי עברה: הגשה, כפילות, בידוד ארגונים,
  מאגר אישי, שינוי סטטוס מורשה, ראיונות וביטול מועמדות.
- כל נתוני תרחיש SQL בוטלו בסוף העסקה. לא נוצרו חשבונות שניתן להיכנס אליהם בתרחיש הזה.
- API חי עם המפתח הציבורי: jobs ו-organizations החזירו HTTP 200 וספירה אמיתית של 0.
- candidates, applications, memberships, candidate_profiles, reward_policies, interviews,
  access_requests החזירו HTTP 401 עבור אורח.
- כניסה עם פרטי חשבון שאינו קיים נדחתה עם invalid_credentials.
- הדפדפן המקומי מציג ספירה אמיתית של 0 משרות מהמסד המחובר.

מה לא הושלם:
- אין עדיין כתובת Preview חיצונית פעילה.
- לא בוצע תהליך משתמש מאומת מקצה לקצה: הרשמה ואישור דוא״ל, כניסה תקינה,
  העלאת PDF אמיתי וקישור חתום, פרסום והגשה דרך ממשק המשתמש וראיון.
- מדיניות תגמולים קיימת כטקסט מוגבל הרשאות; אין סכומים מאושרים או חישובי תשלום.
- אין הזמנות צוות בדוא״ל, מעבר ארגונים, AI פעיל, התראות אוטומטיות או סנכרון יומן.
- כפילויות הן לפי דוא״ל בלבד. מיזוג מארכב את המקור ושומר תיעוד; אינו מאחד אוטומטית שדות.
- עמודי תוכן נפרדים כגון בלוג וחברות לא נבנו במסגרת המשך זה.

- גם הפקודה המאומתת עם environment preview וגם API בהשמטת target,

חסם בדיקות משתמשים:
בדיקת האישור דחתה קריאה של מפתח service_role ושמירתו המקומית לצורך בדיקות,
משום שלא היה אישור מפורש לגישה למפתח הניהולי. קובץ מפתח ניהולי לא נוצר.
הקוד והארכיון אינם מכילים מפתח ניהולי.

להמשך נדרשות החלטות מפורשות:
1. האם לאשר פריסה בפרויקט Vercel החדש בלבד גם אם Vercel מסווג אותה Production,
   כשהאתר מחובר רק למסד הבדיקות, ללא שינוי באתר הקיים או DNS.
2. האם לאשר שימוש זמני במפתח הניהולי של מסד הבדיקות בלבד כדי ליצור משתמשים סינתטיים,
   לבצע בדיקות Auth/Storage מקצה לקצה ולנקותם אחר כך; קובץ סודי זמני יוחרג ויימחק לאחר הבדיקה.
חלופה לסעיף 2: בעל החשבון ייצור משתמשי בדיקה מאומתים ויספק כניסה להם באופן שאינו חושף סיסמאות בצ׳אט.
