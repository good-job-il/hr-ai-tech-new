# CV viewer и контекст представителя клиента

16.11.2026, прямое поручение владельца, HR-11. Исправляем два дефекта демонстрации клиентского пути; это не завершение security acceptance HR-8/HR-12.

## Причины и поведение

- Lockfile и установленный браузерный PDF.js: 6.5.438. Старый статический worker: 6.4.299. После выбора действующего синтетического документа RPC и подписанная ссылка создавались, но PDF.js не показывал страницу. Синхронизация worker с установленной библиотекой устранила воспроизведённый отказ: появился счётчик 1/1, canvas и доступный текст PDF.
- `predev` и `prebuild` копируют worker из установленного `pdfjs-dist` в public с номером версии. Viewer использует ту же `lib.version` в URL. Файл генерируется и исключён из Git. Старый unversioned worker сохранён для прежних клиентов. Не следует запускать Next напрямую без предварительного `node scripts/prepare-pdf-worker.mjs`; обычные npm dev/build выполняют шаг автоматически.
- Home ранее считал любого пользователя без active organization кандидатом. Теперь при отсутствии platform/org роли он проверяет существующий серверный `client_portal_data`. Непустой список разрешённых клиентов даёт контекст представителя в профиле и помощи. Signup metadata не даёт доступ и не заменяет серверную проверку. Ошибка RPC не отображается как успешное определение кандидата. Состояние очищается при смене пользователя; устаревший ответ игнорируется существующим sequence guard.
- В профиле: «נציג לקוח מורשה / Authorized client representative», тип «פורטל לקוח / Client portal», нейтральная подсказка телефона. Меню и возврат ведут в клиентский портал. Platform/org роли сохраняют свой приоритет.
- Помощь представителя объясняет направленных кандидатов, обратную связь, интервью и разрешённые CV. Кандидатские и агентские действия в этот контекст не входят. Кнопка помощи доступна и в самом портале. Она не является AI и не отправляет сообщения.

## Границы

RLS, права, signup, политика anonymous и серверные CV RPC не изменены. Никаких новых прав реальным пользователям не выдаётся. Старые signed URL / CDN revoke остаются отдельным незавершённым HR-8/HR-12 этапом с зависимостью HR-31. Этот UI-fix не выдаётся за устранение той уязвимости. Автоматическая email-доставка не подключается.
