## Журнал и старт будущих миграций

В `supabase_migrations.schema_migrations` ровно 58 записей, версии и имена совпадают с локальными `001–058` без пропусков. Журнал и конечная схема согласованы. Происхождение истории (реальное выполнение или последующая регистрация/repair) по текущему журналу и без лога переноса определить нельзя.

Корректная исходная версия для следующего изменения — **058**, следующий свободный номер в текущем соглашении — **059**. Перед созданием следующей миграции повторно сверить remote/local history и отсутствие уже занятого номера. Новые изменения оформлять отдельным SQL-файлом; существующие `001–058` не редактировать ради повторного применения. Уже созданные таблицы повторно не создавать, стартовые миграции не запускать на этой базе. Не выполнять `db reset`, повторный импорт или массовый `migration repair`. Переход к timestamp-именам CLI согласовать отдельно, сохранив существующие версии.

## Воспроизведение и проверки инструмента

Из корня репозитория, с имеющейся linked Supabase-конфигурацией, `.env.local`, `psql` и сетевым доступом:

```sh
node scripts/migration-reference.mjs /private/tmp/hr-6-reference.json
python3 -B scripts/audit-migration.py /private/tmp/hr-6-reference.json /private/tmp/hr-6-live.json
python3 -B -m unittest discover -s tests -p 'test_migration_audit.py'
```

Сборка эталона из 58 миграций выполнена успешно. Три синтетических теста прошли: совпадение схемы сохраняет результат incomplete без манифеста, отсутствие таблицы и orphan row дают ненулевой exit code. Exit 0 скрипта означает отсутствие расхождений в выполненных проверках; поле `result=INCOMPLETE_SOURCE_MANIFEST_REQUIRED` явно запрещает трактовать его как полную приёмку миграции.

Пределы: каждый пакет запросов имеет отдельный read-only snapshot; активные записи между пакетами могут изменить количества. Это не единый атомарный backup. Проверка не охватывает полную внутреннюю схему управляемых Auth/Storage, расширения, все grants/owners/default privileges, публикации/Realtime, внешние настройки, доставку писем или байты файлов. RLS-определения сверены; полная поведенческая матрица ролей относится к следующим приёмочным задачам.
