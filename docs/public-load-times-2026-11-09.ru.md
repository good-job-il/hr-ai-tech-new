# Реальные времена загрузки: повторная приёмка HR-20

09.11.2026. Запрос владельца: сравнить времена до/после для desktop,phone,iPad, а не только размер файлов.

## Вывод

Устойчивое ускорение загрузки после00d97c0 **не подтверждено**. В контролируемых warm-cache прогонах разница медиан load составляет от−3 до+4ms, LCP от−4 до+8ms; диапазоны перекрываются. Это не доказательство статистической эквивалентности или регрессии, но и не основание заявлять, что сайт стал быстрее. На реальном production наблюдается существенная вариативность TTFB.

## Метод

- Baseline:11c85c2 (до оптимизации); after: web-код00d97c0, тождественный текущему d9ebb7f.
- Обе версии заново запущены как Next production build в одной Windows-среде, на портах3106/3107. Существующая рабочая ветка не переключалась; baseline извлечён из Git в ignored output, БД/RLS не менялись.
- Один IAB Chromium, Hebrew, одинаковые4 фильтра/8 карточек и Supabase. CPU/network throttling отсутствует. Assets предварительно посещены/кэш прогрет; browser cache не очищался. Это проверка повторной загрузки, **не cold-cache или мобильная сеть**.
- Запрошенные viewport:1366×900,390×844,820×1180; фактическая ширина content1351/375/805 из-за scrollbar. Это симуляция размера в одном desktop browser, **не физические телефон/iPad и не эмуляция их CPU/Safari**.
- По5 повторов каждой версии в каждом размере, baseline/after чередуются:30 измерений. Отдельно3 production-after повтора на каждый размер:9 измерений.
- Использован одинаковый существующий opt-in PerformanceDiagnostics без изменения кода: Navigation Timing load/DCL/TTFB и buffered LCP/CLS/longtask, снимок через5s после hydration. UI не трогали до фиксации. LCP валиден в пределах этого окна; если содержание меняется позже, оно не измерено.
- load — событие загрузки документа и синхронно зависимых ресурсов, не время завершения всех AJAX-запросов. В момент снимка во всех39 прогонах присутствовали8 карточек; точное время появления jobs отдельно не инструментировано.
- Исходный cloud deployment найден через GitHub Vercel status, но недоступен подключённому Vercel account (Not Found; deployment API403). Поэтому сравнение before/after **локальное**, а production таблица только текущая. Исторический одиночный baseline не смешивается с новой серией.
