# Общий публичный фонд кандидатов — HR-25

## HR-36: восстановление отображения после временной ошибки, 17.11.2026

Владелец сообщил о прочерке вместо количества. На www после загрузки фактически показано 51 367; четыре свежих анонимных RPC вернули то же реальное число за 776/580/535/536 мс. Исчезновение данных не подтверждено. Прежний код после одного timeout 3 с возвращал null без повторной попытки; focus refresh мог заменить уже показанное значение прочерком.

Подготовлено отдельное исправление: максимум две попытки по 3 с, один общий pending-запрос для одновременных mount/focus callers, последнее успешное значение сохраняется при ошибке обновления. Если первоначально нет ни одного ответа, компонент повторяет запрос через 15 с и при online/focus; таймер и обработчики очищаются при unmount. Пустая конфигурация/ошибка не превращаются в выдуманное число, 0 остаётся допустимым результатом. Агрегат и правила dedup/QA/PII не меняются. Это публичное агрегированное значение в памяти текущего приложения, не копия записей кандидатов.

Пять поведенческих тестов воспроизводят timeout→успех, initial failure→позднее восстановление, refresh failure→сохранение реального значения→новый count, 0/недопустимые значения и concurrent callers. Production-сборка проверена локально в Chromium: desktop 1307×884, phone 390×844, iPad 768×1024, HE/EN через видимый переключатель и проверку реального dir/подписи. Во всех шести случаях 51 367, восемь горячих карточек, четыре фильтра, без горизонтального overflow. Это viewport-проверки, не физические устройства и не облачная приёмка новой версии. [Результаты UI](public-candidate-count-ui-2026-11-17.json).

В открытой публичной вкладке сброшен временный viewport override, фактический размер 1440×900, document width 1425: обрезания по ширине нет. На www видны 51 367 кандидатов, 16 компаний/источников и 364 вакансии. В этом состоянии UI recovery patch ещё не опубликован: его выпуск должен быть подтверждён отдельно; известное обновление безопасности Next.js уже подготовлено в HR-34, публикация HR-34 зависит от HR-35. Локальная сборка на базовом Next.js 16.4.3 показала известное предупреждение безопасности, затем завершилась при повторном запуске; это не причина объявлять production обновлённым.

Счётчик делает distinct по телефону, затем email. Email-only аккаунт/карточка с единственным известным телефоном для этого email привязывается к той же phone identity, чтобы регистрация существующего человека не прибавляла дубль. Это уникальность по имеющимся контактам, не гарантия установления личности при ошибочных/общих/изменившихся контактах.
