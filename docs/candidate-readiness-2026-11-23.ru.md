## Подача и получение

Рабочий Supabase rnstsczayhzrxzcstzpr. Существующий синтетический QA Auth-пользователь, не сотрудник агентства; два реальных публичных jobs из текущего импорта, Civi1055 (Хаци Хинам) и1041 (Мей Эден).

Обычный Auth JWT, без привилегированного INSERT:

- Два INSERT applications получили submitted.
- Повторная подача на каждую вакансию отклонена23505.
- После signOut и нового password login кандидат читает обе submitted заявки.
- Независимый QA-клиент не читает ни одну из заявок.

Это реальная облачная RLS-проверка, но НЕ JWT/PostgREST от имени сотрудника и НЕ проверка его экрана. Для UI владелец приглашён войти в разрешённый аккаунт; его пароль не запрашивается, роль не повышается.

После входа владельца в существующий org_admin аккаунт фактически проверен интерфейс www: «Мשרות ותהליכים» →1055 Хаци Хинам → QA Synthetic Candidate → «פתיחת כרטיס». Совпали должность, статус «חדש», источник «הגשה באתר» и точный уникальный marker текущего запуска. Повторён тот же путь для1041 Мей Эден; карточка открылась с тем же QA run marker под правильной вакансией. Это подтверждение чтения реальным сотрудническим JWT через опубликованный интерфейс, дополнительно к SQL-проверке выше. Не менялись ответственный, стадия, заметки или интервью, сообщений не отправляли.

Массовый кандидатский запуск не принят: старые CV URLs доступны после отзыва, серверная замена/ротация/облачная и UI-приёмка CV остаются незавершёнными. HR-8/12/10 не закрывать.
