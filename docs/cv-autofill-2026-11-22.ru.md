# HR-41: чтение CV и заполнение пустых полей

Решение владельца22.11.2026: читать загруженные CV кандидатов, работодателей и агентств; заполнять поля без удаления существующей информации и без дублей. Источники: HR-41, PDF03.11.2026 стр.6–7 (изоляция, фонд), текущая схема профиля и организационной карточки. Это новое требование после исторического исключения активного AI.

## Реализация и границы

Оба существующих upload-пути предлагают review после успешного сохранения PDF: собственный профиль в Workspace и документы существующей карточки организации в CandidateDocuments (employer/agency). Создание кандидатов из нового файла или массовая загрузка папки здесь не добавляются; существующая карточка не копируется в другой фонд.

PDF.js извлекает текст локально. Страницы без достаточного текстового слоя распознаются локальным Tesseract.js7 с моделями heb/eng. Worker, wasm, модели и стандартные PDF-шрифты подготавливаются из pinned npm dependencies и отдаются с того же origin. Нет внешнего OCR/API-вызова, API-ключа, оплаты или платного fallback. Модели загружаются только при OCR, не при открытии главной. Распознавание на слабом устройстве может занимать время; есть отмена. Технический предел автоматического чтения —30страниц и200000символов, без молчаливой обработки только части документа. Прежние PDF/5MiB upload/storage limits не меняются.

Извлекаются только поддержанные факты: имя, email, телефон, явно обозначенный headline, опыт/образование/навыки/языки и явно обозначенный город. Величины стажа, зарплаты, возраст, интерес к вакансии и даты подтверждения не выводятся из косвенных признаков. Для неразмеченных документов ограниченно распознаётся имя из первой строки; это предложение для проверки, не гарантия правильности. Несколько разных email/телефонов не превращаются автоматически в один контакт. Слишком длинное поле пропускается, не обрезается до якобы полного значения. Niqqud удаляется общим display helper, исходный файл не меняется.

Кандидатский профиль заполняет full_name/phone/headline/experience/education/skills. Email из CV показан для сверки: Auth email не меняется. Город проживания не подменяет preferred_location. Организационная карточка поддерживает также email/languages/city; добавлено поле experience с лимитом8000символов и поддержкой существующего ручного редактора.

## Сохранность и дубли

- Пользователь выбирает предложенные пустые поля и подтверждает заполнение; непустые поля заблокированы для этой операции.
- fill_my_profile_from_cv обновляет только собственный user_id. PK профиля гарантирует одну запись. Предлагаемые user_id/role/organization_id не применяются.
- fill_candidate_from_cv блокирует конкретную существующую строку FOR UPDATE и заново проверяет can_read_candidate, candidates.write и прежнее ограничение owner/candidates.all. Непустые поля остаются неизменными, даже если другой редактор заполнил их после чтения файла.
- Существующий broad save_candidate_professional не используется для частичного заполнения: его прежняя семантика очищает непереданные поля. Новый RPC обновляет whitelisted поля отдельно в одной транзакции. Ключи audit содержат только имена добавленных полей, не текст CV.
- Контакт, конфликтующий с другой карточкой той же организации, отклоняет транзакцию. Доступ/сведения о чужой карточке не раскрываются.
- SHA-256 пути файла стабилен внутри user либо org/candidate. Повторный файл не перезаписывается и не создаёт ещё одну attachment-запись; unique object_path защищает гонку. Старые файлы с UUID-путями не переписываются/не удаляются и ретроспективно не дедуплицируются.
- Ошибка чтения не стирает загруженный файл или профиль; отсутствующая migration/permissions не показывается как успешное заполнение.

## Приёмка и выпуск

Синтетические Unicode PDF и image-only PDF на HE/EN находятся в tests/fixtures/cv-autofill. Фактически проверены извлечение и OCR полей; SQL tests на PGlite проверяют self/employer/agency, повтор, сохранение полей, изоляцию и контактный конфликт. Эти проверки не являются входом через hosted UI или проверкой рабочего Supabase.

Фактический итог локальных проверок23.11.2026: полный suite108/108 PASS; повторный PDF/OCR suite2/2 PASS после добавления самостоятельной подготовки ассетов для чистого CI; финальная production build и встроенный TypeScript PASS. В более ранней сборке были таймауты prerender с повтором; свежая последовательная сборка завершилась без этих предупреждений (compile4.8s, TypeScript2.8s, static pages903ms). Эти времена стадий сборки не являются замером загрузки сайта. Ранее существовавшие dependency versions не обновлялись; добавлены только OCR и две языковые модели с lockfile.

До выпуска требуется применить069_cv_autofill.sql в согласованной тестовой среде, пройти browser upload→review→save→reload в HE/EN и desktop/phone/iPad, затем выполнить обычный release. Статус кода/локальные проверки не означают, что функция уже доступна на www. Vercel access/release —HR-35; исходный server secret для отдельных облачных проверок —HR-31. Текущая автоматизация Chrome отклонена, а в новой внутренней вкладке Codex доступно только открытие URL: визуальная приёмка не утверждается. Ничего Орэну не отправлять.

Технические первичные источники: [Tesseract local installation](https://github.com/naptha/tesseract.js/blob/master/docs/local-installation.md), [API](https://github.com/naptha/tesseract.js/blob/master/docs/api.md); фактические сигнатуры сверены с установленными tesseract.js7 и pdfjs-dist.
